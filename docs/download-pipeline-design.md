# 下载链路的职责与机制约束

本文以 v0.4.26 的实现为基准，约束后续修改。具体恢复时序见[下载恢复边界](download-recovery.md)。已实现约束与待迁移接口分别列出，不能把线上样本恢复视为架构重构完成。

## 核心问题

请求头、代理、OCR、错篇章和重复下载看似是不同故障，实际跨越了同一条下载链路。只在报错位置增加分支，容易让搜索、重试、重启恢复和归档各自执行不同规则。设计上必须分清五类事实：

| 对象 | 含义 | 负责模块 |
| --- | --- | --- |
| 目标与偏好 | 要哪个篇章、哪一集，以及需要什么画质、字幕 | 番剧元数据、偏好策略 |
| 来源候选 | 哪个规则、详情页、线路能提供目标集 | 编排器选择，源适配层解析 |
| 执行尝试 | 某一次取流、预检、传输，以及这次尝试的错误 | 下载服务、执行器 |
| 媒体资产 | 已验证的文件、正式路径和剧集映射 | 媒体验收、归档流程 |
| 派生状态 | 当前是否缺集、品质是否达标、规则是否健康 | 存储审计、质量审计、健康聚合 |

站点目录返回候选不等于身份已经确认；下载器接单不等于下载完成；任务曾完成不等于文件现在还可用；字幕暂时无法识别也不等于字幕一定不合格。

## 一条执行链，不同入口共用

```mermaid
flowchart LR
    A[自动补集 / 手动重试 / 重启恢复] --> B[目标与候选身份复核]
    B --> C[捕获实际请求上下文]
    C --> D[容量与媒体预检]
    D --> E[传输至独立暂存文件]
    E --> F[成片验收]
    F --> G[竞速仲裁与归档]
    G --> H[剧集映射与质量审计]
```

编排器决定“下一步尝试谁”，下载服务决定“任务能否转换状态”，源适配层只负责目录和播放页的站点差异。BT 引擎负责实际任务及清理日志，不能自行决定剧集已入库。

人工选源可以明确接受偏好差异，仍需结构完整性和参考片长校验。它是明确的产品入口，不应成为自动恢复的隐式兜底。

## 必须保持的约束

1. **身份复核贯穿恢复入口。** 订阅标题、展示名称和历史绑定都不能充当站点身份凭据。搜索与执行使用相同的集数语义；倒序列表不按位置猜集，部分编号列表不补猜编号。合并篇章需要可验证的映射，不能靠总集数相减猜偏移。
2. **候选身份与播放签名分开。** 流媒体冷却身份是番剧、集数、规则、详情页、线路；临时 CDN URL 更新不能获得新的快速预算。另一线路也不应继承本线路的耗尽次数。
3. **一次尝试共用请求上下文。** 保留浏览器实际请求头，包括没有 Referer 的情况。预检、抽帧和传输沿用通过验证的路由；对代理输入故障的一次直连探测不能改写全局代理设置，也不能绕过字幕或画质拒收。
4. **超时必须有层级预算。** 抽帧、单次 OCR、单帧后备识别和整个字幕检查各有上限，并响应取消。增加单阶段预算时必须检查总体预算、并发限制和后备机会，不能只把报错阈值调大。
5. **证据不足与执行失败分开。** OCR 超时不证明繁中；真实繁中不需要以网络故障反复重试。低置信度、重复字幕和简日共用字不能凑出简中证据。自动下载继续满足 1080p、简中和参考片长要求。
6. **容量按尚需写入量准入。** 使用可用空间、其他在途任务剩余体积和本任务预估体积，保留配置的余量。HLS 清单字节数不代表成片大小；配置为 0 的语义由设置契约确定，不能被真假值判断替换成默认值。
7. **重试执行与重新搜索分开。** 搜索失败不消耗执行次数，轮询时间不刷新实际失败时间。快速预算、候选长冷却与规则半开探测各有作用域；恢复不能通过创建新记录、重启或签名变化重置预算。
8. **完成必须经过验收与仲裁。** BT 提交成功只代表引擎接单。单集暂存文件验收后才能参与归档；暂停、淘汰或失败后的迟到回调不能复活任务。重复回调不得重复通知或覆盖正式文件。
9. **跨存储操作必须能恢复。** 数据库提交、文件移动和 BT 清理无法共享一个事务。必须保存恢复所需的意图，按顺序执行并允许幂等重放；不能先删数据库记录，再把引擎或 NAS 残留交给临时脚本猜测。
10. **品质升级不能破坏当前可用性。** 只有已确认完结、且有明确品质债务的番剧才进入整季升级；单纯 unknown 不触发整季重下。缺集、字幕或画质不优可共同构成升级理由。新合集全季验收完成前保留旧文件和映射。

## v0.4.16 成片验收与恢复

远程预检负责身份、分辨率、参考片长和容量；硬字幕证据未知时不进行反复网络跳转，进入隔离传输，完成后在本地识别。未知证据只能推迟判定，不能授予语言证据或入库资格。流媒体目录标题不能证明成片字幕。

`validation_pending`、`file_path`、`validation_final_path` 保存传输已经结束但尚未通过验收的成片。此时体积已计入磁盘使用，不再作为待下载空间重复预留。工具或归档故障写入明确失败与退避；Orchestrator 在搜索缺集前，优先 CAS 认领尚有预算的暂存验收。显式重试和重启恢复共用这条路径，重新读取当前目标与字幕证据，不重新访问失效播放链接。文件丢失则撤销暂存状态，回到普通选源；路径越界或符号链接不能借恢复路径入库。

本地验收共用流媒体并发配置，并支持取消等待和运行中的检查。取消与自动恢复的预算不可由回调复活。耗时工具检查在全局归档锁外执行，只有重读候选状态、竞速仲裁和文件提升需要串行化；移动成功但事务提交失败时仍从现存成片恢复。

## v0.4.15 已落实的边界

| 边界 | 实现与职责 |
| --- | --- |
| 身份判断 | `stream/source_identity.go` 统一目录身份匹配和线路组织，配合共享编号与总集数边界；搜索负责选优，执行负责复核历史绑定 |
| 失败语义 | `failure` 保存稳定原因和阶段，`download` 计算退避；规则与番剧健康消费同一事实。历史文案解释集中在 `failure/legacy.go`，第三方工具的 stderr 仍需在工具边界适配 |
| 质量策略 | `mediapolicy` 统一默认值、配置校验与番剧覆盖；编排与验收读取失败均停止，显式全局空数组与番剧空覆盖的语义不同且有契约测试 |
| 质量证据 | 新资产先清除旧质量结论，归档事件主动触发审计；同番剧事件合并，审计期间的新事件不会丢失；定时审计继续负责重启和失败恢复 |
| 恢复与健康 | 工具检查、存储、数据库、取消、品质拒收与来源网络故障区分；候选预算与规则半开探测继续分开 |
| 归档与清理 | 单集归档可重入；BT 有持久化删除意图和幂等清理；整季升级保留备份。传输完成后的检查工具失败保留暂存路径，不以坏媒体处理 |

### 失败结果契约

结构化结果同时服务重试、候选切换、健康统计和诊断。原因与阶段保存到下载记录，作用域由候选身份确定；重试时刻由恢复策略计算，错误产生处不各自安排定时任务。

| 原因 | 恢复作用域 | 是否证明规则不可用 |
| --- | --- | --- |
| 身份、画质、字幕或片长明确不符 | 当前候选拒收，尝试其他候选 | 否 |
| 抽帧、OCR 工具超时或不可用 | 当前检查的有限重试或本地修复 | 否 |
| 目录、播放页或媒体输入网络故障 | 对应阶段和候选退避，必要时规则半开 | 可作为该阶段可用性证据，不能直接证明全站故障 |
| 磁盘、权限、数据库故障 | 本地修复，保留已下载文件及恢复信息 | 否 |
| 取消、竞速淘汰 | 终止当前尝试 | 否 |

新执行结果携带结构化语义，恢复与健康聚合共同消费；历史记录通过单一兼容适配器读取。展示文案与稳定原因分开，任务状态、失败种类和健康状态各自只表达自己的含义。

## 后续演进与验收方式

后续扩展继续形成可独立验证的改动，保持以下回归边界：

1. 固定失败结果契约及兼容边界，统一恢复和健康的判定来源。测试文案变化、错误包装、OCR 超时、真实字幕拒收和取消，确保它们不改变业务分类。
2. 收敛目标与偏好策略，再收敛纯身份匹配规则。对自动下载、明确重试和重启恢复跑同一组契约用例，覆盖空配置、覆盖值、错篇章和倒序编号。
3. 明确媒体证据到剧集质量状态的更新机制，验证归档后审计、偏好变化和文件替换，确保 unknown 不引起重复整季升级。
4. 持续验证竞速归档、整季替换及 BT 清理的中断恢复：在意图写入、文件移动、数据库提交和清理之间注入故障；恢复后核对文件、映射和引擎状态。

回归应验证这些约束，而不只是给每段新条件补一个同形测试。真实验收仍需核对目标篇章与集数、完整成片、1080p、简中、正式映射和原有媒体保留情况；仅 HTTP 成功、任务变绿或单测通过都不足以证明下载正确。

## 修改评审约束

- 每个业务判断说明归属：目标策略、候选选择、执行结果、资产验收或派生状态，避免多个模块各自决定同一件事。
- 新增站点差异放在规则或适配层。公共恢复和归档代码不增加特定番名、集数、域名的特判。
- 新增超时、重试或兜底时说明预算、作用域、取消路径和终止条件；数据库读取失败不能当成没有限制。
- 一次线上处置与长期程序机制分别记录。线上脚本成功不能作为软件已具备同等恢复能力的证据。
- 改变策略时同步更新机制文档、注释和契约测试，避免旧说明引导后续开发恢复已经修正的行为。


## v0.4.17 内容证据与尝试投影

媒体证据独立于候选来源与用户偏好。完整本地成片经归一化的视频码流 SHA256 得到 `video_hash`，`media_evidence` 按该指纹与识别器版本保存硬字幕事实。重新封装、来源 URL、InfoHash 或目标偏好改变，不会重置已经确认的内容事实；完整视频变化或识别器版本变化会重新检查。原生字幕轨仍按当前文件检查，不能把没有简中轨的版本拒收结论继承给新加了简中轨的相同视频。工具故障只保存到当前尝试，不能作为全局内容事实。

`subtitle_evidence` 保存方法、实际画质、时长、抽样时刻、帧哈希、有效文字、语言、执行计数及未知/故障原因；无论满足还是不满足用户偏好，都保留事实。`verified_languages` 是兼容字段，不能脱离内容绑定直接授予验收资格。目录/种子标题只用于候选排序，不能取代自动成片的实际字幕检查。

远程预检先读取当前媒体自己的字幕轨。只有仍不满足目标时，才比较同一剧集旧成片的证据：分辨率及时长一致，并在有界预算内精确匹配两个包含已确认字幕的不同画面，才可复用确定的字幕拒收；未知证据需要四个不同画面一致，仍保持未知。该匹配只用于跳过已检查视频的重复传输，不能断言完整文件哈希，不能入库。画面变化、匹配失败或超时继续当前候选的独立验收，不能假定相同内容。重编码、时间偏移和字幕变化没有精确匹配时仍需检查，不能通过片名或近似图像直接认定重复。

OCR 保留常规字幕的完整区域及高对比识别，在读不到有效文字时定位文字组件行，并从描边中分离字形。描边后不同语言模型可能高置信度地归一化简繁；新增区域识别只把独立读数一致的字形作为证据。仍执行原有置信度、独立字幕、简日共用字和多个区分字的门槛。整体/单帧/单次识别均有预算，取消可传播；未识别到文字不会被伪称简中。

待复核使用 `failure_code=subtitle_unknown`、`failure_kind=review`。它是没有获得入库资格的成片，不是源不可用或已确认繁体；保留文件及恢复路径，排除盲目自动重验和快速重试。用户可请求异步复核，复用同一成片和当前策略，展示运行状态；复核只更新事实与原因，不跳过候选身份判断直接归档。重试和完成回调不能复活已暂停/淘汰的任务。BT 单集的检查故障同样保存完成后的暂存阶段，恢复不重新提交种子。

下载页默认消费后端的当前剧集投影，按番剧、集数与任务目的汇总。活动尝试、已存在可用成片、暂停任务和最新未解决结果依次优先；整季任务保持自己的范围。统计来自全部分组，不受最近 500 条限制，并分别显示候选不符合、字幕待复核、证据复用、执行故障。每一条历史尝试都保留，可按剧集分页查看；升级与普通补集不合并。历史证据不足不能追认成繁体，兼容投影保守归为待复核。

## v0.4.24 之后的架构复核与自动门禁

这批 11 集已经完成真实成片验收。复核同时发现，运行时恢复契约和代码依赖方向需要比个别故障用例更强的约束。

### 已落实

- **BT 控制意图统一转换。** 暂停、并发排队、完成后的停止接收共用下载器适配层的 `setDownloadDemand`，先撤销分片需求再禁止数据接收；恢复顺序相反。只调用底层禁止接收接口会留下不同步的待请求分片，已通过独立进程的公开调度接口稳定复现。修复不增加等待、不禁用断言、不依赖站点或特定剧集。撤销需求是分片优先级的内存操作，不删除数据；代价是在控制转换时遍历分片，避免引入第二份持久化分片状态。

- **画质解释独立于搜索。** `internal/mediaquality` 定义现有画质标签及分辨率，排序、偏好解析、成片验收共同使用。下载服务与偏好策略不再依赖 indexer，既有别名、默认 1080p 和简中要求不变。
- **依赖方向由测试检查。** `internal/architecture` 扫描所有平台的正式 Go 文件：测量、标题解析不依赖业务调度；下载器适配层不依赖业务数据库与剧集管理；执行/验收不反向依赖搜索和编排。测试夹具验证嵌套目录、平台文件和别名导入，不能只检查当前 Linux 构建恰好用到的文件。
- **生产运行时必须独立通过。** `backend-contracts.yml` 在 PR、main 和正式发布复用同一组检查：原生 CGO + mmap，以及与 Docker 一致的 `CGO_ENABLED=0` + classic。每种配置运行完整后端测试、依赖检查与 vet，生产配置另构建服务端；原生配置另运行 BT、下载、媒体检查、编排和流媒体的竞态测试及浏览器恢复夹具。桌面包继续使用各平台发布任务规定的构建标签。发布依赖两组后端检查，不能只验证桌面适配器后直接构建生产镜像。
- **恢复测试模拟真正进程退出。** BT 准备进程退出后，再启动恢复进程，默认目录与任务目录分离；连接种子前必须从磁盘恢复全部正确前缀并排除损坏分片。测试不能调用显式重新校验来补救生产恢复行为，也不能借同进程 DB 锁冲突的内存后备路径获得假通过。

测试数据库夹具统一采用已有的纯 Go SQLite 驱动，使 CGO=0 的全套业务测试可执行；生产数据库选择不受影响。这两组测试验证运行时及业务契约，不等于 PostgreSQL 多进程锁与事务集成验证。

这些检查约束职责和恢复行为，不是对当前文件布局做快照，也不代替真实 NAS、代理和成片验收。

### v0.4.26 对协议依赖的复核

线上日志显示，在移除字幕待复核候选时，BT 库因分片可用性计数不一致而断言退出。真实 TCP 对端按 HAVE_ALL、HAVE_NONE、HAVE 的顺序发送消息，可复现同一断言；没有线上原始协议抓包，不能断言本次线上连接的具体消息序列。暂停时分片需求的修复不解决另一份对端库存记账。

规则归属仍在协议状态的拥有者：`PeerConn.peerSentHaveNone` 清空库存前，统一调用已有的可用性撤销逻辑，同时处理完整种子集合和逐片计数。没有在业务下载服务中重写库存、过滤消息、吞掉 panic 或关闭协议扩展。最新已发布依赖仍为 v1.61.0，因此保留完整模块与许可证，通过本地 module replacement 携带这一处改动。CI 将全部文件与 Go 校验和验证过的上游版本比较，只允许文档列明的单处源差异。

代价是暂时维护约 3 MiB 依赖源码；相比引入未发布版本的无关变化，修复范围可审查。上游版本包含相同修正后，应先通过协议生命周期、暂停队列、跨进程恢复和 NAS 契约，再删除整个替换目录。新的协议测试在独立进程中使用真实握手与消息，覆盖两种存储模式、完整/部分库存、重复库存转换、移除与客户端关闭。

BT 库仍嵌在后端进程中，依赖的其他未发现 panic 仍有进程级影响；本次没有宣称完成独立下载进程的故障隔离。后续是否拆进程，需要一并设计命令幂等、事件重放、任务归属与部署成本，不能只在调用处加入 recover。

隔离 PostgreSQL + NAS 的真实 BT 端到端测试还发现：普通下载地址不含 InfoHash 时，执行器已经返回引擎确认的 hash，但接单分支只保存 `torrent_id`，同步器按 `info_hash` 筛选会永久漏掉该任务。接单现在在同一次有状态条件的更新中保存两者；有效的引擎回执优先于来源 URL 的推测。历史缺失映射仅在同步器实际观察到同一引擎任务时补齐，未知运行 ID、缺失任务、终态与暂存验收不借此改变状态。回执仍只授予跟踪传输的资格，完成须经原有成片验收和仲裁。

Linux 构建依赖安装由共享的 `.github/actions/linux-build-deps` 负责，后端和桌面调用者只选择依赖集合。归一化同时覆盖活动的 `sources.list`、`.list`、`.sources`，保留第三方源、忽略备份文件，并验证幂等；单独修改一个配置文件不能证明 APT 的实际来源已切换。安装继续有有限重试、网络超时和 15 分钟整体上限。调用者锁定构建 action 的完整提交 SHA，与应用 tag 分开固定：构建基础设施可修正后重放，仍检出同一应用 tag，不能为解决构建问题移动已经公开的应用 tag。更新共享 action 时需同时审查源码、运行其契约测试并更新调用者的固定提交。

### 仍需迁移的接口与边界

| 当前耦合 | 目标边界 | 迁移验收 |
| --- | --- | --- |
| `Executor.Execute` 的 `Result` 同时表达 BT 接单和流媒体暂存文件，调用者根据任务类型补充解释 | 执行结果显式区分接单凭据、传输产物和终止事实；只有验收服务能授予入库资格 | BT 接单永不成为完成；流媒体产物验收未知不能入库；自动、手动和恢复入口消费同一结果 |
| `QBitSyncer` 与 provider 字符串状态、60 秒完成抑制阈值绑定 | provider 输出统一传输事实；协调器根据元数据、完整字节和验收阶段判断，不根据 provider 名称或任务年龄猜测 | 新任务 60 秒内真实完成可以进入验收；旧任务缺少元数据时永不完成；检查、暂停和迟到回调不会跳过仲裁 |
| `mediapolicy.Load` 的数据库读取和纯偏好解析同包；部分 ffprobe 进程调用仍在应用服务内 | 数据读取适配与策略快照分开；工具调用、预算和错误归一化由媒体检查端口负责 | 搜索、预检、归档恢复读取同一偏好；父取消和工具故障不会变成质量拒收；不复制第二份 JSON/字幕解释规则 |

上述是已确认的结构性债务，不等于已复现的新线上故障，也不宣称已经完成迁移。迁移保留现有数据与 API，逐个替换调用者，并在契约用例一致后删除旧入口；避免并存两个状态机或两个质量判断中心。

### 每次修复的评审顺序

1. 写清失败事实、可复现条件、实际责任模块与模块之间违反的约定。
2. 比较局部处理和模块机制调整：影响范围、兼容成本、额外 I/O、并发与恢复语义分别是什么。
3. 选择唯一的规则归属，说明哪些上层只消费结果；新增接口要解释它隔离了什么变化。
4. 先固定会失败的行为契约，再验证修复、取消、重启和依赖不可用；不能在测试中偷偷增加生产没有的恢复步骤。
5. 通过共享发布门禁，再做真实失败样本、正式映射与原媒体保留验收。测试通过、外部来源可用、媒体已归档分别报告。

## v0.4.27 保留资产、字幕测量与品质替换

来源冷却只控制远程尝试，不能使本地待验收文件失效。编排器通过下载服务核实同一规则、详情页、线路的保留资产；安全可读时等待本地恢复或明确复核，其他线路继续选源。文件丢失才允许重传，读取或路径错误停止本次规划。取舍是同一稳定入口不会仅因发布者可能替换内容就每日重下；当前版本不自动证明该入口的远端内容已经变化，新的线路和 BT 候选仍独立尝试。

字幕识别器负责测量，不安排重试。主字幕行定位、描边分离、LSTM 识别和两种语言优先顺序的一致文字构成一条有界检查链；分散抽样应对短片对白稀疏，240 秒整体预算、40 秒单帧和原置信度/独立画面/区分字门槛继续生效。发行版默认语言模型会改变测量结果，因此镜像和 CI 由同一固定提交、SHA256 清单安装模型。改变模型或算法必须提升识别器版本并实际验证简体、繁体和未知样本，不能继承旧版本的入库资格。

工具失败按抽样保存阶段、耗时和稳定原因，不保存请求头、签名 URL 或任意 stderr。内容缓存只存非工具故障的事实，来源字段记录实际产出该事实的尝试；具有相同视频指纹但没有复用检查结果时，不展示为复用旧证据。

品质替换与普通抢先归档分开。只有确认完结、当前映射存在明确质量债务时，单集候选才进入严格目标验收；人工选源或全局回退不能放宽替换标准。单集与整季共同调用 `commitUpgradeJournal`：预先保存移动意图、暂停文件访问、移动并保存旧版、提交映射、解析不确定的提交结果，最后封存日志。启动时通过同一恢复入口重放或回滚，并补齐引擎清理；没有并存另一套升级状态机。普通竞速仍不能替换可用且符合要求的赢家。

这一机制保留既有的单后端进程协调方式；SQLite 的故障注入和单进程 PostgreSQL 端到端不代表多主实例共享 NAS 的完整事务证明。前述接口迁移及 BT 进程隔离债务继续保留。

BT 内容身份和执行尝试身份不能互相覆盖。新记录的 `torrent_id` 保持 Service 分配的稳定尝试 ID，确认的引擎内容身份写入 `info_hash`，provider 操作统一由 `executorTaskID` 选择后者；剧集归属和回调引用前者。历史使用 hash 作为 `torrent_id` 的记录不改写，旧缺失身份仍只根据真实引擎快照恢复。同一内容的后续尝试不能与历史记录争用唯一键，无有效接单身份也不能停留在假活动状态。隔离 PostgreSQL 的真实 BT 复用用例用于验证这一边界。

混合种子的协议身份也归属于 BT Client 的唯一注册表。v0.4.27 在回调可见前同时注册已知 v1/v2 别名，移除时一起撤销；Tracker 仅在注册成功后发布键，活动请求始终解析当前 owner。已移除一代的 HTTP 返回不能覆盖新代的公告状态或投递 peer，旧弱引用仅供 detached Stopped 收尾。真实本地 HTTP Tracker 与两种 TCP 握手在独立进程验证，包含元数据未到、移除重加、延迟响应与关闭。注册失败保护回移自上游 PR #1079；别名与代际修正经过独立失败回归，四个依赖源文件的精确摘要均由 CI 核验。选择受控回移的代价仍是维护依赖替换，不能把它说成完成 BT 进程隔离。

可复用的端到端入口为 `scripts/e2e-download-contracts.py`，在 Linux Docker 主机安装 Python libtorrent、预载 PostgreSQL 16 镜像后运行：

```sh
python3 scripts/e2e-download-contracts.py --image leeyang1990/anidog-backend:v0.4.29 --retention-probe /path/to/linux-scheduler.test --workspace /tmp/anidog-contract-run-unique --media-parent /path/to/test-media
```

workspace 必须是新目录；脚本为每次运行创建独立内网、PostgreSQL、BT 状态及媒体子目录，经普通 HTTP API 验证合格/低清/繁体/未知、相同内容再次接单、旧单集质量审计与安全替换、旧版和新版 SHA256、重启与容量零值保存。seed 由本地 HTTP Tracker 正常发现，不向应用注入 peer 或补做生产没有的修复。可选 `--binary` 仅用于候选服务端验收；正式镜像验收应省略。结束清理此次容器和网络，保留成片与证据；私有临时凭据不进入报告。

## v0.4.28 协议身份与证据生命周期

BT provider 的接单回执使用完整内容身份：优先 v1，纯 v2 使用完整 SHA256。20 字节短键仅属于协议库的 Tracker/握手注册表；任务控制、数据库、快照、元数据缓存和 manifest 不引用该短键。恢复时核实持久身份确实是元数据中的别名，保留原接单身份；v2-only magnet 后来发现混合元数据时不更换键。输入缺少身份或没有有效协议键会在调用库前失败，不捕获 panic 作为正常控制流。受控依赖变更仍由精确源摘要检查保护。

`service/downloadrecord` 统一表达记录的保留引用，下载器不读业务数据库。自动维护仅删除没有证据、复用、媒体映射或升级备份引用的过期淘汰记录；显式删除来源也先检查证据引用。`OriginDownloadID` 和 `EvidenceReusedFrom` 的 RESTRICT 外键是数据库并发边界，避免一个事务清理后另一个事务仍插入悬空来源。保留期限不是解除引用约束的授权，证据正文也不因来源过期而丢弃。

代价：有引用的元数据可能超过 90 天继续保留，需要对引用列建索引；用户删除必要的来源会收到 409 冲突。迁移保留现有字段与记录，既有悬空引用应先核实修复，不能为建约束静默清空来源。两连接 PostgreSQL 合同覆盖并发删除提交/回滚和引用插入，不能用 SQLite 的串行结果代替。

端到端脚本还要求 `--retention-probe /path/to/linux-scheduler.test`。该测试二进制从同一源码通过 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go test -c -o /tmp/linux-scheduler.test ./internal/service/scheduler` 构建，在隔离网络与数据库中执行实际维护与外键合同；只有名为 fixture 的测试数据库允许执行，凭据不输出。正式镜像验收省略 `--binary`，保留旧版素材备份与完整哈希检查。

显式删除在文件操作前锁定来源记录，直到删除事务提交：PostgreSQL 使用行锁，SQLite 在读取前取得写保留，避免引用在检查与文件操作之间插入。代价是下载器删除期间占用该锁；文件删除与数据库提交仍不是跨系统原子事务，下载器失败保留记录，不能据此宣称完成多主文件事务迁移。SQLite 两种驱动的每条连接均启用外键；仅在迁移连接执行一次 PRAGMA 不能保护后续连接。

纯 v2 多分片回归另外固定初始化与哈希到达的请求调度约定：完整建立分片清单后再发布回调，待办集合包含数据与缺少哈希的元数据工作，哈希到达后重新计算请求资格。出站握手在客户端锁内取得身份快照，网络 I/O 不持锁；后到的混合元数据别名不能造成读写竞态。断言和哈希校验继续启用。

## v0.4.29 SQLite 迁移与运行连接的边界

逐连接启用外键与旧表重建属于不同阶段。SQLite 迁移器重建带自引用的表时，临时表仍引用旧表；直接在执行外键的连接上删除旧表会失败。`database.migrateSchema` 在启动、业务任务尚未运行时固定单条连接，迁移前关闭该连接的外键执行，在单个事务中重建并执行 `foreign_key_check`；所有引用有效才提交，否则回滚整个schema和数据。事务结束后无论结果都恢复并核实连接的外键执行，再交还连接池。其他连接继续执行外键，PostgreSQL 继续使用原生AutoMigrate路径。

代价是SQLite表重建期间的写锁；不合法的旧引用会阻止启动，必须调查真实来源，不能以清空引用换取升级成功。原生和桌面驱动回归验证有效旧数据/来源保持、非法引用回滚、连接恢复和幂等。v0.4.28发布在这项补查发现问题后取消，保留公开tag，以新版本发布完整修正。

Linux原生CI进一步验证了恢复初始化的发布边界：存储可能直接报告已有完整分片，其完成回调会开启连接，并不经过优先级触发开关。协议库现在先建立全部分片的请求顺序和缺哈希待办，再逐个读取完成事实、发布回调；不靠标志位隐藏尚未完成的清单。保留实际CI失败栈及存储完成回执夹具、真实v2恢复回归，继续检查classic/mmap和race。

## v0.4.31：观测、评估与来源可用性

字幕工具产生测量事实，纯评估函数产生语言结论；下载应用负责文件身份、证据来源和是否可归档。`caption-v3` 固定已有提帧、模型与置信度合同，`subtitle-v4` 仅改变冲突与局部工具失败的合并语义。已有足够简繁冲突不得被后续超时抹掉，也不得批准简中。完整视频摘要、尺寸及片长一致后，只能复用已知合同的原始样本恢复未知冲突；不能通过迁移授予正面语言。纯工具故障、未知版本、文件改变需要实际重测；显式复核可刷新。软字幕轨继续独立验收。

`indexer.SearchResult` 将候选与请求可用性一起穿过索引、缓存和调度边界。请求失败不是空结果，部分来源失败不阻挡健康来源。故障及部分结果短缓存一分钟，使同轮多集共享故障观测且不会占用正常二十分钟缓存；真实空结果仍按正常 TTL 缓存。诊断只包含来源名，不向用户泄露原请求或代理细节。此策略增加故障持续时的请求频率，代价是恢复更快；不引入额外调度器或后台重试循环。当前轮次仍由现有调度周期触发。

Nyaa provider 只负责动画候选召回，不隐含英文偏好；画质、字幕及最终媒体准入仍走同一策略。OCR仍可能归一化简繁文字；本次不声称解决了所有识别误差，也不降低置信度或以目视结论改库入库。外部代理故障需要另行观测，错误传播改善不代表网络永远可用。
