# v0.4.27

下载清单的实际复核发现，保留成片在来源冷却过期后可能再次下载，字幕读数和检查超时也没有表达清楚。此次修复统一保留资产的调度边界、字幕测量和升级切换，保持 1080p、简中及禁止偏好回退。

- 混合 v1/v2 种子的两个已知哈希在元数据和 Tracker 回调前共同注册。移除重加时使用当前归属，旧代延迟请求不会覆盖新任务；晚到的 Tracker 注册必须成功后才能记录，保留依赖断言。
- BT 尝试保留自身稳定 ID，引擎确认的内容哈希单独保存，避免再次使用同一内容时与历史唯一键冲突并停在 0%。缺少有效接单身份时明确失败，不假称已接单。
- 同一规则、详情页和线路已经有安全可读的待验收文件时，继续本地检查或复核；冷却到期不会重新传输。其他线路仍可使用，文件丢失后可重新获取，存储错误停止选源。
- 硬字幕检查先定位主字幕行、识别描边内的字形；双语小字行不参与主行的简繁投票。显式使用 LSTM 引擎，以两种语言优先顺序的相同读数作为证据。增加分散的对白抽样，仍保留 240 秒总预算、单帧预算、独立画面与区分字门槛。
- 识别器升级到 subtitle-v3，检查失败保存抽样时刻、分阶段耗时和稳定失败原因。工具故障不写入内容缓存；“复用证据”的来源绑定实际检查结果，重新检查不会误指向旧尝试。
- 测试和正式镜像共用固定版本、校验和验证的中文模型。模型安装有重试上限，失败不覆盖原模型；不以系统发行版的不同默认模型代替正式运行条件。
- 完结番剧中已确认质量不足的单集，可由严格验收通过的候选替换。它与整季升级共用文件切换日志、回滚和提交结果恢复；旧文件及字幕保留备份，未知质量不触发替换。重启后补齐已提交升级的映射及引擎清理。

回归覆盖保留文件与冷却、检查来源、简繁实际字幕图、取消与工具故障、单集和整季切换、提交确认丢失及重启恢复。正式镜像还需经过独立 PostgreSQL、真实 BT、NAS 和正常 API 的端到端验收，再更新生产容器。
