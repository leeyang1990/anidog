# AniDog v0.4.13

修复流媒体请求上下文丢失、CDN 路由不通、字幕检测误判、重试放大和内嵌 BT 部分删除后的状态不一致。

- 媒体请求使用浏览器实际发送的 UA、Referer、Origin 和 Cookie，保留没有 Referer 的请求。移除 Range、缓存和代理认证等仅属于单次请求的头；同一上下文贯穿预检、抽帧和整集下载，Cookie 限于媒体域名，敏感头不输出到 JSON 或诊断日志。
- 继承代理的媒体访问失败时，只允许一次直连预检。通过后固定使用直连，不修改全局代理或显式直连规则；画质和字幕拒绝不会触发路由回退。
- 抽帧允许 45 秒，字幕识别有独立时限和整体 4 分钟上限。执行失败与字幕不符分开分类。对白采样、重复台词排除、双语字幕行分离、白色字幕背景处理和冲突字的双通道一致性校验提高证据获取能力，仍要求高置信度、多张独立画面、至少六种简体特征字及中文专有特征，未知或繁中不会当作简中归档。
- HLS/DASH 清单大小不再当作完整视频体积；使用码率、时长或保守估算预留待下载空间。
- 快速重试预算按具体规则、详情页、线路和集数计算。耗尽候选从每天一次逐步退避至每周一次；坏源的恢复探测通过数据库原子领取，未结束的探测继续占用门闩。源健康统计只计算真实完成及可用性失败，站点非成功 HTTP 响应直接报告错误。
- BT 删除先提交引擎清理日志；NAS 清理失败单独重试，重启后继续处理。数据库先事务保存放弃意图和黑名单，再移除引擎任务；失败的部分操作可幂等恢复，旧巡检不能删除已完成的任务。恢复清单失败时保留原始清单。
- 用户明确重试会清除旧失败预算和字幕证据，并实际重新执行 BT/流媒体任务；保留合集范围与原始偏好。尚在清理的 BT 不会被复活，移除失败时保留数据库记录。

回归覆盖请求上下文、媒体探测/抽帧/传输、路由回退边界、字幕执行失败与简繁证据、HLS 容量预留、候选退避、半开门闩、真实终态健康统计、BT 故障恢复和并发状态保护。
