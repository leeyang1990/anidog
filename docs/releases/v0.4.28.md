# v0.4.28

此版本构建在发现旧 SQLite 迁移兼容问题后取消，未部署；正式修复见 v0.4.29。

纯 v2 种子曾因缺少 v1 哈希触发后端断言，过期候选清理也可能删除字幕证据的来源。本次按协议身份与引用生命周期两个边界修复，保持 1080p、简中及禁止偏好回退。

- 纯 v2 在 provider 中使用完整 64 位身份，握手与 Tracker 的 20 字节键由协议库管理。元数据补充别名后，接单回执、快照、控制与重启恢复继续使用原身份；v1、混合种子的既有身份保持兼容。无有效身份的输入在进入协议库前返回错误，保留协议断言。
- 清理和删除共用下载记录引用规则。持久字幕证据及复用记录由数据库外键保护；维护任务还保留当前媒体映射和升级备份的来源。无引用的过期淘汰记录继续按 90 天策略清理，最后引用释放后可清理。用户删除被引用的来源返回明确冲突，文件操作前先检查引用。
- 增加原生与生产配置的纯 v2 生命周期、别名、传输与重启回归；增加 PostgreSQL 并发删除/引用写入测试，观察真实锁等待、提交及回滚结果，并接入发布门禁。
- 正式镜像端到端使用独立 libtorrent、Tracker、PostgreSQL 与 NAS，验证纯 v2 的暂停重启、真实传输、严格成片准入及完整 SHA256，同时保留原有合格/低清/繁体/未知与安全替换用例。

- 多分片 v2 的初始化、哈希获取及请求顺序在协议库内统一维护，保留完整断言；握手在网络操作前读取一致身份快照，消除元数据补别名时的竞态。
- SQLite 原生及桌面驱动逐连接启用外键。显式删除持有来源写锁直到提交，避免引用检查后、文件操作前出现并发新引用。
