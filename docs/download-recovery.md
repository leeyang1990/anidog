# 下载恢复边界

本规则由 Docker 服务端与桌面端共用的 Go 后端执行，不在平台层分叉。

## 完成、可用与暂停

- `completed` 是一次任务曾完成的历史事实；`media_missing` 是经存储审计确认的当前状态。
- 竞速赢家、失败收口、完成状态校准只承认 `completed && !media_missing`。丢失媒体的旧完成记录保留，不阻止新候选归档。
- 不在竞速事务里访问 NAS 来推断丢失。存储审计先验证下载根目录健康；网络盘暂不可用不能直接当作文件删除。
- 持有番剧锁后重新读取候选状态；只允许 pending/downloading 完成。暂停、失败、淘汰后的迟到回调不能复活任务。
- 完成仲裁在服务实例内串行化，同时保留数据库事务锁：桌面 SQLite 不支持 `FOR UPDATE`，不能只依赖 PostgreSQL 的行锁语义。下载传输本身仍并行。
- 重复完成不再次通知、不删除正式文件；补齐可能因进程退出而未同步的剧集状态。
- 已存在正式文件且暂存文件也存在时拒绝覆盖；两者都保留供检查。暂存文件已移动而数据库未提交时，允许继续完成状态登记。
- 暂停任务仍覆盖对应剧集；暂停合集按声明范围覆盖，避免自动调度绕过用户暂停创建逐集替代任务。

## 搜索不等于执行

- `retry_count` 只表示下载执行的重试序号。初次执行为 0，后续任务继承失败链的下一序号，上限 3；搜索未入队不增加次数。
- 下载失败退避为 10 分钟、1 小时、6 小时；快速预算耗尽后改为长周期探测，不无限恢复快速预算。
- 重试任务每 5 分钟检查到期的最新 transient 失败；同番剧合并搜索，每轮最多 50 部。
- 无候选、读取失败、存储不可用或搜索过程中取消，均将本轮处理的失败记录安排到 30 分钟后再搜索。没有处理的批次不改动。
- 调度只更新 `next_retry_at`，不改写实际失败时间 `updated_at`。旧版本遗留的空重试时间也会重新纳入搜索。
- 搜索期间已被真实成功任务收口的记录不再改写；较旧失败的搜索时间不能覆盖较新失败的退避策略。
- 未订阅、已归档番剧不启动恢复；手动未关联番剧/剧集的任务不参加自动重试。

## 流媒体候选隔离

候选身份使用“番剧 + 集数 + 规则 + 详情页 + 线路”，不使用会过期的 CDN 视频签名。

| 情况 | 行为 |
| --- | --- |
| 当前线路失败 | 优先选同站可用线路，再搜索备用站 |
| 单线路规则 | 不越过配置选择其他线路；等待或换站 |
| 不同站点线路同名 | 冷却互不影响 |
| 详情页已更换 | 旧详情页失败不封锁新详情页 |
| 临时网络错误 | 同一候选按执行退避时间重新开放 |
| 截断、过短等拒收 | 该候选冷却 24 小时，其他候选可立即选择 |
| 快速预算耗尽 | 冷却 1 小时后有限探测 |
| 本地权限、磁盘等错误 | 保留本地故障分类，6 小时后允许探测；不伪装成站点故障 |
| 整个规则 broken | 尊重规则级 1 小时熔断；缺少故障时间时等待健康检查修复 |
| 所有候选冷却中 | 明确返回等待原因，不能兜回刚失败的候选 |
| 历史记录缺少详情页/线路 | 在该规则内保守匹配已知维度，同样有冷却期限 |

当前规则与备用规则使用同一选择过程；禁用规则不参与。查询失败不能绕过冷却。仅在任务创建成功后保存新的首选来源。

## 可观测性与范围

FFmpeg 失败在任务记录保留脱敏、限长的关键 stderr，移除 URL、认证与 Cookie；保留原始退出码。任务错误截断保持 UTF-8 有效。

自动恢复不保证外部站点必然有可用资源。所有来源缺集、NAS 持续不可用、已存在的正式文件冲突等情况需要等待外部状态变化或人工处理，不能通过放宽成片校验、覆盖文件或把失败标成成功来结束。

回归测试覆盖媒体丢失补下载、历史失败收口、迟到回调、重复完成、搜索取消与批次限制、空重试时间、候选冷却与站点/线路隔离。真实外部站点恢复效果仍需部署后观察，不能仅凭单测通过宣称线上缺集已补齐。

验证命令（在 `backend` 中运行）：

```sh
go test -count=1 ./...
go test -race -count=1 ./internal/service/download ./internal/service/orchestrator ./internal/service/scheduler ./internal/service/stream
go vet ./...
CGO_ENABLED=0 GOOS=linux go build ./...
go build -tags desktop,nosqlite ./...
```

构建遵循已有 Dockerfile/桌面发布脚本的配置：服务端关闭 CGO，macOS 桌面端使用 `desktop,nosqlite`，避免两个 SQLite 实现的 CGO 重复符号；不修改全局 Go 环境。
